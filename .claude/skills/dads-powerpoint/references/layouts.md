# レイアウトと情報表現

先に資料の目的、主要テーマと説明順序、各スライドの役割・タイトル・必要な情報を整理し、その構成に合う表現方法と配置を選ぶ。専門知識のない人の理解を助けることを基準に、文章、図解、データ、写真・イラストを使い分ける。色や書体とフレームを共通にしながら、内容に応じて配置を変える。以下はスライド向けの応用例で、公式のPPTXコンポーネントではない。

| 伝える内容 | 組み方 | 注意点 |
| --- | --- | --- |
| 表紙 | 大きな題名＋短い副題。所属・日付が必要なら下部に置く | 題名を要約文や大きな画像と競わせない |
| 章の切替え | 章番号と見出し、必要なら一文の導入 | 分割そのものが理解を助ける場合だけ挿入 |
| 概念説明 | 全幅の要点＋2〜3個の説明、または説明と一つの図 | 段落の長さを無理に揃えない |
| 用語の定義・短い説明 | 簡潔な文章と必要な具体例 | 専門用語や略語を説明し、前提知識を省略しない |
| 並列の要素・条件 | 箇条書きや項目の一覧 | 並列性のない説明や連続した文章を無理に分断しない |
| 実物・現場・利用場面 | 写真または説明に適したイラスト＋短い説明 | 読者が何を見ればよいかを示す。装飾のためだけに増やさない |
| 選択肢の比較 | 共通の軸を縦に揃えた2列または比較表 | 同じ情報順序と粒度で比較し、長い文章同士なら列間を広くする |
| 数値の変化 | 大きな主要値＋グラフと単位・期間 | 実測値と例示値を区別 |
| 手順・因果 | 少数のノードと関係を示す矢印、長い説明は下段か別ページ | 箱と矢印だけの長い横一列を避ける。接続線はノード背面 |
| 出来事の時間的な関係 | 日付や期間に沿ったタイムライン | 順序・間隔・期間の意味を明確にする |
| 抽象的な構造・関係 | 要素とつながりを整理した概念図 | 用語だけを並べず、関係の意味を説明する |
| 仕様・一覧 | 意味のある列見出しを持つネイティブの表 | 表を配置用コンテナにしない。過剰なセル結合を避ける |
| 要確認事項 | 通常の説明に短い注意ブロックを一つ追加 | 状態名を明記し、赤や黄の装飾面を増やさない |
| まとめ・次の行動 | 話の結論＋必要な判断・行動 | 一律に「ありがとうございました」で終わらせない |

## 表

列見出しと項目の対応、同種の値の桁・単位、読み順を優先する。見出し行は薄い青地＋濃い文字、または濃い青地＋白文字とし、十分なセル内余白を取る。不可欠な罫線にはGray-600などの色を用いる。行列が増えたら文字を縮める前に主題で分割し、続きページにも見出し行を置く。

表の見出し属性・読み順など、生成ライブラリだけでは保証できない要素を確認済みと報告しない。

## グラフ

数値比較は棒、時間推移は折れ線など、値の関係を把握しやすい形式を選ぶ。ネイティブのチャートを優先し、3D装飾を加えない。値ラベルと単位を見やすく置く。軸の範囲や省略で差を誇張しない。

単系列はBlue-900を基本に、複数系列は濃い補助色を追加する。系列名の直接表示、点の形状、線種なども用いて色に依存しない。見栄えだけの数値は作らない。動作確認のサンプルを求められた場合だけ、例示データと明記して使用する。

## 図・画像・箇条書き

簡単な関係図は編集可能なPowerPoint図形を使う。図にする必要のない短い説明は文章や番号で示す。装飾用の疑似アイコンを図形で量産しない。

ZIPにある画像リンクやキャプションは画像ファイルそのものではない。公式アイコン・ロゴ・図版を使用する場合は実物と利用条件を確認する。代替説明は画像が伝える情報を書き、情報を持たない装飾と区別する。

箇条書きの折り返した行は字下げを揃える。ユーザーが🔹を指定している場合はその表示を確認し、文字化けや揃いの問題があれば日本語を扱えるフォントとインデントを調整する。
