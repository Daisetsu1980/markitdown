# スライド作成の流れ

スライドをいきなり作らない。次の四段を順に進め、各段の中身は、名前を挙げたスキルとエージェントに任せる。ここでは順序と止まる場所だけを決める。

## 0. 受け取る

目的、読者、元の資料、分量、既存のpptxの有無を確かめる。判断に必要な不明点だけを、まとめて一度だけ聞く。作業フォルダ `work/<案件名>/` を作る。

## 1. 構成のブラッシュアップ

`dads-powerpoint:dads-powerpoint` の内容整理（目的から重複と説明不足の確認まで）を行い、`outline.md` にまとめる。

次に `slide-reviewer` に構成レビューを頼む。渡すのは `outline.md` と元の資料のパスだけにし、作った側の意図や言い訳は添えない。指摘は、直すべきものから直す。構成の直しは2周まで。

直したら、構成案をユーザーに示して承認を待つ。**承認が出るまで2へ進まない。** ユーザーが最初から「最後までそのまま進めて」と言っているときだけ、示すだけで進む。

既存のpptxの改稿では、変更を頼まれた範囲だけを対象にする。

## 2. 原稿化と推敲

承認された構成に従い、スライドごとの見出し・本文・発表者ノートを `script.md` に全文で書く。次に `yomiyasu` で `script.md` の本文を推敲する。

yomiyasu に渡す条件は次の三つ。

- 文体はだ・である体のまま変えない。
- 見出しと箇条書きの体言止め、箇条書きの形を保つ。地の文に崩さない。
- 事実、数値、固有名詞、出典を変えない。

yomiyasu が返す「変えたところ」などの注記は `script.md` に入れない。推敲後の本文だけを採用する。

## 3. スライドの作成

`script.md` の文面をそのまま使い、`dads-powerpoint:dads-powerpoint` でpptxを作る。この段で文面を書き換えない。文面に問題が見つかったら、`script.md` に戻して2をやり直す。

## 4. 描画・検査・修正

1. `scripts/render.sh work/<案件名>/<案件名>.pptx` で全ページを画像にする。
2. `python3 scripts/check_pptx.py work/<案件名>/<案件名>.pptx` で機械的な問題を拾う。
3. `slide-reviewer` に完成レビューを頼む。渡すのは画像のフォルダ、`script.md`、2の出力だけにする。
4. 指摘を `review.md` に写し、直す。文面の指摘は `script.md` に戻して2からやり直す。デザインの指摘は3で直す。
5. 1〜4を、指摘がなくなるか3周に達するまで繰り返す。

## 5. 納品

pptxの置き場所とファイル名、残った指摘（あれば）を報告する。作業の経過は報告しない。補助ファイルは、頼まれなければ納品物に含めない。
